# CloakKit v2.0 — 为「其他设备」实现 SideStore 式远程安装 · 架构方案

> 蓝本：开源项目 **SideInstaller**（`com.frizzlem.sideinstaller` v1.2.1，作者 frizzlem，iOS 18）。
> 目标：在 iOS App 内，不依赖电脑，通过无线调试（RemoteXPC / CoreDeviceProxy）发现、配对并向**同一局域网内的其他 iOS 设备**安装/侧载 IPA。

---

## 1. SideInstaller 逆向结论（来自对 IPA 二进制与 Info.plist 的实证分析）

### 1.1 它用了什么技术栈（二进制内嵌的 Rust 模块路径）
- `vendor/idevice/...`：**jkcoxson/idevice-rs (idevice crate)** —— pymobiledevice3 的 Rust 移植。
- `vendor/idevice-ffi/...`：idevice 的 C FFI 层（afc / core_device_proxy / dvt / house_arrest / installation_proxy / lockdown / misagent / mobile_image_mounter / pairing_file / rp_pairing_file / tunnel_provider）。
- `vendor/isideload/...`：**isideload crate** —— Apple ID 登录 / GrandSlam / Anisette(v3) / 证书 / AppID（与我们 v1.x 已调研的引擎同源）。

### 1.2 关键服务与协议（strings 实证）
- Bonjour 广播/发现：`_remotepairing-pairable-host._tcp`（iOS17+ 远程配对主机）、`_sideinstallerprobe._tcp`（自有设备发现）。
- 隧道：`CoreDeviceProxy::create_software_tunnel`，服务 `com.apple.internal.devicecompute.CoreDeviceProxy`，RSD（Remote Service Discovery）+ XPC/HTTP2（`xpc/http2`）。
- 安装：`com.apple.mobile.installation_proxy.shim.remote`（`InstallationProxyClient::install/upgrade/uninstall/get_apps`）。
- 挂载开发者镜像：`com.apple.mobile.mobile_image_mounter.shim.remote` + `mount_personalized_with_callback_rsd`（个性化 DDI，仓库 doronz88/DeveloperDiskImage）。
- 证书/描述文件：`com.apple.misagent.shim.remote`；文件：`afc.shim.remote`、`house_arrest.shim.remote`；锁定：`com.apple.mobile.lockdown.remote.trusted`、`wireless_lockdown`。
- 配对文件：`.mobiledevicepairing`（UTI `com.frizzlem.sideinstaller.mobiledevicepairing`），支持导入/导出。
- Anisette：v3 provisioning（start/end provisioning、ptm/tk），与我们 v1.3+ 一致。

### 1.3 Info.plist 关键配置（复刻清单）
- `NSBonjourServices = [_remotepairing-pairable-host._tcp, _sideinstallerprobe._tcp]`
- `NSLocalNetworkUsageDescription`（本地网络权限）
- `BGTaskSchedulerPermittedIdentifiers = [...pairing]`（后台配对任务）
- `UIBackgroundModes = [audio, location]`（保活，配对/安装期间防挂起）
- `LSApplicationQueriesSchemes = [localdevvpn]`、`CFBundleURLSchemes = [sideinstaller]`
- `CFBundleDocumentTypes`：IPA（`com.apple.itunes.ipa`）+ `.mobiledevicepairing`
- `UTExportedTypeDeclarations`：自定义 IPA 与 pairing UTI
- `UIDeviceFamily = [1,2]`（iPhone + iPad），全方向

### 1.4 决定性可行性结论（已在本机构建链实测）
1. **idevice 0.1.68 可在 iOS arm64 成功交叉编译**，features：
   `rustls + ring + usbmuxd + tcp + core_device + core_device_proxy + remote_pairing + installation_proxy + mobile_image_mounter + misagent + afc + house_arrest + rsd + xpc + tss + amfi + dvt + application_listing`（实测 `Finished release`，17.8MB staticlib）。
2. **software tunnel 不依赖系统 Network Extension / VPN entitlement**：`create_software_tunnel` 使用 **jktcp 纯用户态 TCP/IP 栈**（`tcp::adapter::Adapter`），把隧道跑在一条普通 TCP 流上。因此**个人免费证书 + SideStore 侧载即可运行**，这是 SideInstaller 能成立的核心。
3. 与我们现有工程同源：isideload 已验证可编译，idevice 本就是 isideload 的依赖，依赖图收敛、无陌生黑库。

## 2. 安装链路（端到端）

```
[发现设备]  Bonjour 浏览 _remotepairing-pairable-host._tcp / _sideinstallerprobe._tcp
     │        （idevice::mdns；iOS 需本地网络 + Bonjour 权限）
     ▼
[建立配对]  路径A（首选）：导入 .mobiledevicepairing（由电脑/另一设备生成）
           路径B：App 作为 pairable-host 广播，走 RemotePairingClient 交互式 pair
     │        （remote_pairing: tlv/opack/tls_psk，pair / attempt_pair_verify）
     ▼
[远程隧道]  TcpProvider(设备IP, PairingFile) → lockdown 取 RSD 端口
           → CoreDeviceProxy::new → create_software_tunnel()  [jktcp 用户态]
     │        得到 Adapter（本地虚拟 IP ↔ 设备），无需 VPN entitlement
     ▼
[准备环境]  检查开发者模式；按需 mount_personalized DDI（mobile_image_mounter + TSS）
     ▼
[安装 IPA]  tunnel 上连 installation_proxy.shim.remote
           InstallationProxyClient::install_with_callback（推送 + 进度回调）
     │        （如需自签：先用 isideload 证书/AppID 重签，再经 misagent 下发描述文件）
     ▼
[完成]      回调进度 → UI；get_apps 校验安装结果
```

## 3. CloakKit 工程落地方案

### 3.1 Rust 内核（cloakkit-core）
新增依赖（features 见 1.4）：`idevice = "0.1.68"`；复用现有 `isideload`（登录/签名）。
新增模块：
- `src/device/discovery.rs`：mdns 发现（`ck_devices_start / ck_devices_next / ck_devices_stop`）。
- `src/device/pairing.rs`：导入/解析 `.mobiledevicepairing` → `PairingFile`；交互式 pair 封装。
- `src/device/tunnel.rs`：TcpProvider → lockdown/RSD → CoreDeviceProxy → software tunnel（全局持有 Adapter，保活）。
- `src/device/install.rs`：tunnel 上 installation_proxy 安装/卸载/列表；进度通过回调写共享缓冲（FFI 轮询）。
- 复用：`macho.rs / ipautil.rs`（校验）；isideload 账号（证书/AppID/重签，下一阶段）。

FFI（C ABI，保持现有命名风格 `ck_*`，线程内建 tokio runtime）：
```
ck_devices_scan(timeout_ms) -> 句柄
ck_device_list(handle) -> JSON [{udid,name,ip,paired}]
ck_pairing_import(path) -> 0/错误
ck_tunnel_open(udid|ip) -> 0/错误
ck_tunnel_status() -> JSON {client_ip,server_ip,mounted,developer_mode}
ck_install_ipa(tunnel, ipa_path) -> 任务id
ck_install_progress(id) -> JSON {phase,percent,message}
ck_apps_list() -> JSON
ck_app_uninstall(bundle_id) -> 0/错误
```
错误统一走现有 `ck_last_error`，返回结构化 JSON（含中文可读 message）。

### 3.2 Swift UI（UIKit，沿用现有 4 Tab + 新增）
- 新增 **「设备」Tab**（或并入「应用」）：
  - 设备扫描列表（Bonjour 实时发现，显示名称/IP/配对状态）。
  - 配对：导入 `.mobiledevicepairing`（UIDocumentPicker）或交互式配对引导。
  - 隧道状态卡（client/server IP、开发者镜像、开发者模式）。
- 「安装」页增强：选择**目标设备** → 导入 IPA → 隧道 → 安装进度条（轮询 ck_install_progress）。
- 「应用」页：经 tunnel `get_apps` 列出目标设备已装应用，支持卸载。
- iPad：沿用 v1.4 响应式 ReadableWidth；列表在 iPad 用更宽可读上限/分栏。
- 全部字体 Dynamic Type。

### 3.3 Info.plist（对齐 SideInstaller，写进 build_ios.sh 模板）
- NSBonjourServices 两个服务、NSLocalNetworkUsageDescription、
  BGTaskSchedulerPermittedIdentifiers、UIBackgroundModes(audio/location)、
  CFBundleURLSchemes、LSApplicationQueriesSchemes(localdevvpn)、
  CFBundleDocumentTypes（ipa + mobiledevicepairing）、UTExportedTypeDeclarations。

### 3.4 构建与验证（沿用已打通的 Linux→iOS 交叉链）
- `CC_aarch64_apple_ios=clang -target arm64-apple-ios16.0 -isysroot iPhoneOS16.4.sdk`，
  `[lib] crate-type=["staticlib"]`；ring 走预生成汇编（pregenerated 目录保留）。
- 静态库并入 build_ios.sh 链接；ldid ad-hoc；产出 raw IPA。
- 校验：Mach-O/CodeDirectory cdHash 一致（现有 verify_ipa + Python 独立重算）、
  新增单测（pairing 文件解析、安装进度 JSON 状态机）。

## 4. 现实边界与风险（必须如实说明）

1. **首次配对是最大门槛**：iOS17+ 远程调试通常要求设备端已有可用配对记录。
   - 最稳：导入电脑（Xcode/pymobiledevice3/SideStore）生成的 `.mobiledevicepairing`。
   - 纯手机对手机的「交互式远程配对」在系统层面支持不稳定（需要目标设备处于可配对状态、同 Wi-Fi、并在弹窗信任），不是所有 iOS 版本都能无人值守完成。SideInstaller 同时支持「导入 pairing」与「广播等待」，我们按此双路径实现。
2. **目标设备要求**：开启开发者模式 + 无线调试；iOS17+ 首次可能需挂载个性化 DDI（需联网向 Apple TSS 取 personalized manifest）。
3. **「安装到其他设备」与「自签重签」是两件事**：
   - 若 IPA 已被有效签名（如开发者证书签的），经 installation_proxy 直接装即可。
   - 若要用本机 Apple ID 免费证书重签后再装到**别的设备**，受限于免费账号的设备注册数量（每账号 10 台/年）与描述文件下发（misagent），这条链路要叠加 isideload 的 dev 模块，作为第二阶段。
4. **网络**：两台设备需同一可达局域网；mdns 发现受本地网络权限与路由器 Bonjour 转发影响，必要时支持手动输入 IP 兜底（TcpProvider 支持直连 IP + PairingFile）。
5. **签名/entitlement**：software tunnel 走用户态栈、不需 Network Extension entitlement，这是好消息；但 `UIBackgroundModes` 的 audio/location 保活在 App Store 审核不允许——我们只走 SideStore 侧载分发，不上架（与项目现状一致）。

## 5. 分阶段交付建议

- **v2.0（本方案主体，先打通闭环）**：
  idevice 集成 + Info.plist + 导入 `.mobiledevicepairing` + 手动/扫描 IP +
  software tunnel + installation_proxy（安装已签名 IPA / 列表 / 卸载）+ 设备/安装 UI。
  → 形成「电脑导出 pairing → CloakKit 无线给其他设备装 IPA」的可用闭环。
- **v2.1**：Bonjour 全自动发现 + 交互式远程配对（pairable-host 广播）+ 个性化 DDI 自动挂载。
- **v2.2**：叠加 isideload dev 模块（本机 Apple ID 免费证书重签 + AppID/证书管理 + misagent 下发），对齐 iLoader 的 AppIds/Certificates 页。
